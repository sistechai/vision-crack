# VisionCrack: crack width from a smartphone photo and a 1D barcode

Code and data for the paper

> **Smartphone-Based System for Fine Crack Width Measurement Using 1D Barcodes under Consistent Capture Conditions**
> *(journal, year and DOI to be added on acceptance)*

VisionCrack puts a small printed label (50 × 30 mm, a custom 18-bar 1D barcode) next to a crack. The phone app only
captures a photo when the label fills a fixed guide, is fully visible and is upright. The known label size then gives
the millimetre-per-pixel scale (**reference-based scaling**), and the crack width is read from a binarized crop.
The method uses no extra hardware and no machine learning.

On printed reference widths of 0.55–2.75 mm, VisionCrack's mean absolute error was **0.061 mm**, against **0.164 mm**
for ten inspectors with crack gauges. Its standard deviation was **0.0086 mm**, against **0.118 mm**.

## Repository layout

```
src/visioncrack/   core method (ROI, corner detection, gates, width, scale, error model)
notebooks/         one notebook per figure / table, numbered in paper order
data/              dataset description; full data on Zenodo, a 1-image sample in git
mobile/            capture app (Flutter): guide box, corner detection, gates, save to gallery
scripts/           download / package data, run all notebooks
tests/             unit and regression tests (pytest)
```

## Quick start

```bash
git clone <this repo> && cd visioncrack
python -m venv .venv && source .venv/bin/activate      # or: conda env create -f environment.yml
pip install -r requirements.txt
python scripts/download_data.py                         # ~155 MB into data/raw/ (Zenodo)
bash scripts/run_all_notebooks.sh                       # ≈ 2 min; figures/tables → results/
```

Measure one capture in Python:

```python
import visioncrack as vc
caps, inspectors = vc.load_table1()
roi = vc.preview_roi(image_wh=(2160, 3840), screen_wh=(430, 932))   # paper Eq. 1–5
m = vc.measure_capture(vc.read_rgb(caps.path[0]), caps.bbox[0], roi)
print(m.widths_mm)        # [0.644 1.066 1.757 2.229 2.823]  = "VisionCrack 1" in Table 1
```

Supplementary notebooks (not in the paper):

| Topic | Notebook |
|---|---|

Every notebook **asserts** its key numbers (the published ones where the paper prints them), so a changed result stops the run.
Figures that are drawings or photos (overview, label design, field use) are not generated by code.

### Notes on exact reproduction
* The original analysis converted RGB images with OpenCV's `BGR2GRAY`, which swaps the red/blue weights.
  `measure_capture(..., paper_compat=True)` (the default) keeps this; `False` uses the standard conversion
  (ET-1 changes by ≈ 0.007 mm).
* Table 1 summary rows are computed from the 3-decimal values as printed and rounded half-up (`metrics.half_up`).
* The paper's "MAE vs. GT" is |mean of 10 readings − GT|. Notebook 05 also reports the per-reading MAE.

## Mobile app

`mobile/` is the guided-capture app (Flutter, Android and iOS). It has one screen with your captures and a
**Capture** button. The photo is taken automatically when the three gates pass, and it is saved to the phone
gallery with a JSON file holding the corners and gate values. There is no server or login. See `mobile/README.md`.
`src/visioncrack/detection.py` and `gates.py` are ports of its detector. Notebook 02 and `flutter test` check
that both find the phone's corners on the sample capture (≤ 2 px).

## Printing the label

The label is 50 × 30 mm. The bar classes 1–5 are 0.5–2.5 mm wide; the code table is in `src/visioncrack/barcode.py`.
Print at 100 % scale (no "fit to page").
